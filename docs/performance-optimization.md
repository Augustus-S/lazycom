# 性能优化实现

日期：2026-09-28。依据 [源码审查](performance-review.md) 实现接收坐标复用、
有界显示缓存、按需重绘、增量搜索和日志追加路径优化。未运行应用、测试、
benchmark 或 profiler；以下说明源码变化，不代表实测性能收益。

## 实现

| 路径 | 变化 |
| --- | --- |
| `src/ui/receive_view_model.cpp` | 坐标在记录范围与过滤器不变时复用。全部方向可见时直接使用 deque 坐标；过滤索引在容量允许时只处理追加部分，淘汰、清空或过滤变化时重建。 |
| `src/ui/tui.cpp` | 25 ms tick 与 worker 唤醒通过合并的 FTXUI closure 推进状态，仅可见状态变化时追加重绘事件。保留键盘、鼠标、resize、动画与定时状态推进。 |
| `src/ui/tui.cpp` | 按终端高度与其他面板占用限制记录行数量。按稳定 record ID 和 RX/TX 显示模式缓存安全文本节点；光标标记与样式在缓存外叠加。 |
| `src/ui/receive_view_model.cpp` | TUI 搜索固定提交时的查询、方向、显示模式与记录 ID 上界，分批扫描。显示搜索进行中状态，允许导航已找到的结果；切换方向、重新提交或退出会替换或取消旧查询。 |
| `src/logging/linux_session_files.cpp` | 普通追加复用本次 inventory 刷新结果，未删除文件时省去末尾目录 stat。轮换后仍刷新，删除前仍复核文件身份、owner、权限及配额。 |
| `src/logging/session_writer.cpp` | 在队列出队的同一临界区更新记录数和字节数，省去原先处理记录时的额外一次加锁。 |

## 资源与语义边界

- UI 与 Application 使用同一预算对象。过滤索引和显示缓存计入 `UiRecords`，
  增量搜索的查询与结果存储计入 `Model`，均保留既有类别上限。
- 过滤索引预留容量最多 1000000 项，预算不足时退回无分配扫描；记录不会因索引
  分配失败而隐藏。显示缓存含条目元数据最多 200 项、2 MiB；大行或预算不足时
  直接渲染。缓存只持有安全文本，不持有原始记录 payload。
- 搜索每批最多 256 条，以 512 KiB 原始 payload/消息和 2 ms 为让出阈值。
  单条记录保持完整，可能超过字节或时间阈值；这不是硬实时上限。
  结果最多 10000 个稳定 ID，记录淘汰后移除对应结果，提交后追加的记录不参与
  当前查询。存储预算不足时显示错误提示。
- 搜索预算和缓存接入不代表全局 128 MiB 运行时预算已闭环。其他尚未接入的类别
  仍见 `Plan.md` 与 `DevelopPlan.md`。
- 日志继续逐条编码与写入，保留部分写错误归属、FIFO、flush 和 barrier 语义。
  本次未引入批量写入；其收益及错误处理方案仍需另行评估。

## 剩余性能限制

过滤模式下，头部记录被淘汰仍会重建索引；低预算下的扫描回退也可能较慢。
显示缓存避免重复安全投影与文本节点创建，FTXUI 在实际重绘时仍会计算布局和字形。
定时器仍每 25 ms 唤醒，优化的是无变化时的重绘工作。增量搜索降低单次扫描规模，
没有消除无匹配查询的总扫描量，单条大记录的投影成本仍然存在。
