## 核心模型与安全边界

早期阶段建立了稳定错误码、强类型身份、显式 `Result<T>`、连接和交互状态机，
以及三个 TOML 配置文件与 NDJSON v1 会话日志格式。随后接入串口 owner、分帧、
日志、完整 TUI 和快捷发送；早期报告中的“仅有启动展示界面”已不代表项目状态。

2026-09 的交互与安全修复确立了以下边界：

- 发送草稿只在请求被接纳后清空；同步拒绝保留内容与编辑位置。括号粘贴作为
  整段有界文本处理，不能借换行或控制字符触发快捷键。
- 接收浏览以跨连接稳定 record ID 定位，先过滤再截取视口。手动暂停、是否位于
  底部、当前记录和覆盖层状态分别维护，帮助与错误弹窗恢复原编辑上下文。
- RX 观察时间、TX 输入模式和最后一次正写返回时间在事实发生处捕获。
  部分发送失败时保留操作系统已接受的前缀，不能把终结通知时间当作发送时间。
- 配置写入保留未提交、已提交、已提交但耐久性未知三种结果。保存完成携带
  本次提交的文件身份，避免通过重读路径错误接纳其他写者的版本；读取先以
  nonblocking/no-follow 打开，再验证普通文件、所有者、权限和尺寸。
- 日志轮换、断开和退出分别等待所属会话的收尾边界。串口 Cleanup 与日志文件
  关闭是独立条件，旧会话的迟到结果不能改变新会话；停止始终保留 deadline。

持久格式、安全输入处理和可靠 completion 一直是保留边界。配置替换仍存在
[文件安全规则](../Plan.md#125-文件安全规则) 记载的同 UID 不合作写者最终窄竞态，不能将
身份复核描述为对所有外部写者的完整隔离。

## 架构收敛与精简

2026-09-17 至 2026-09-20 的架构调整在 `2de2ae4` 中归档。重构主要消除了
内部字符串协议、重复状态、反向模块依赖和 UI/log 的 payload 副本。

| 职责 | 调整后的归属与原因 |
| --- | --- |
| 设置与持久化 | `SettingsCoordinator` 持有三份文档的提交身份、保存状态和候选，Application 处理命令与展示结果。 |
| 日志生命周期 | `SessionLogCoordinator` 持有 writer、轮换、backlog 和关闭 deadline；Linux 文件安全与配额实现独立于异步 writer。 |
| 记录与浏览 | `SessionRecords` 持有分帧、唯一 `SessionSequencer` 和可见记录；`ReceiveViewModel` 管理过滤坐标、稳定游标与搜索导航。 |
| 定时发送 | Scheduler 由既有 serial owner 推进，并合入 I/O deadline；发送时序不再依赖 UI tick。 |
| 模块边界 | worker 信号、身份和文本基础能力归入低层模块；设置接口与覆盖层使用具名类型，删除无消费者的通用事件和队列包装。 |

Application 继续负责连接状态机、事件归并、跨组件断开与正常/FATAL 退出，
上述职责拆分没有引入额外线程或通用消息总线。

共享记录最终收敛为单个不可变
[`SessionRecord`](../include/lazycom/model/session_record.hpp)：同时拥有 payload、
元数据和预算 token，UI 与日志共享其生命周期，按单条记录淘汰。中间方案中的
`SharedPayload`、`ByteSlice` 和单记录批次包装已删除；会话内 seq 与跨连接
record ID 仍是不同身份。UI 淘汰不能提前释放日志仍持有的存储预算。

预算模型在构造时验证分类上限之和不超过 128 MiB，再按类别原子预留和 RAII
归还，避免额外全局计数的竞争。此机制只覆盖显式接入的分配，不能据此宣称
进程内存或完整运行时已受统一 token 约束。

同期测试维护减少了重复准备和孤立模型检查，保留实际输入、持久化和异步边界。
旧报告的测试项数、代码行数与微基准采用不同阶段的基线，不构成当前覆盖率或
整机性能指标；共享记录的微基准也不包含真实串口、磁盘和完整日志编码成本。

## 接收与日志性能优化

`52bd179` 同时落实了基于源码审查的性能优化：

- 接收坐标在记录与过滤器不变时复用；全部方向可见时直接使用原坐标，过滤索引
  在容量允许时只处理追加部分。索引预算不足时退回无分配扫描。
- 接收行按可见高度生成，安全文本缓存最多 200 项、2 MiB。缓存按 record ID
  和 RX/TX 显示模式复用，不持有原始 payload；大行或预算不足时直接渲染。
- 定时器与 worker 唤醒通过合并的 FTXUI closure 推进状态，仅可见状态变化时
  发送重绘事件。25 ms tick 保留，idle 分帧、通知到期与 completion 继续推进。
- 搜索固定提交时的查询、方向、显示模式与记录上界，分批扫描并显示进行中状态。
  每批最多 256 条，以 512 KiB 和 2 ms 为记录边界让出阈值；单条记录可能超过
  字节或时间阈值。结果最多 10000 个 ID，旧查询可取消，淘汰记录从结果中移除。
- 普通日志追加复用一次 inventory 刷新结果，出队记账合并到原临界区。
  删除文件前仍复核身份与权限，日志仍逐条编码和写入，保留 flush/barrier 顺序。

新增过滤索引与文本缓存使用共享 `UiRecords` 预算，搜索存储计入 `Model`。
过滤后的头部淘汰仍会重建索引；无匹配搜索仍需遍历保留记录，FTXUI 在重绘时
仍需计算布局和字形。这些变化没有实测 CPU、RSS、吞吐量或 UI 延迟收益。
